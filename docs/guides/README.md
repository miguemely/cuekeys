# CueKeys guides

Step-by-step guides for using CueKeys. Start with **Getting started**; the rest can be read in any
order.

| Guide | What you'll do |
|---|---|
| [Getting started](getting-started.md) | Install the app and the keypad firmware, and deploy your first layout |
| [Lock your computer with one key](lock-your-computer.md) | Make a key that locks your Mac (or Windows / Linux PC) |
| [Macros, text and hold keys](macros.md) | Key combos, typed text, delays, recording, tap vs hold, held modifiers |
| [Layers](layers.md) | More pages of keys: next/previous, jump to a layer, hold for a temporary layer |
| [Colours and LEDs](colours-and-leds.md) | Key and layer colours, the live preview, and LED colour balance |
| [The on-screen overlay](overlay.md) | What it shows, where it goes, and changing its opacity from the keypad |
| [Lighting consoles: grandMA and MIDI](lighting-consoles.md) | grandMA3 over OSC, grandMA2 over Telnet, MIDI notes and MIDI Show Control |
| [Bitfocus Companion](companion.md) | Use part of the keypad as a Companion surface with its own pages |
| [Several keypads](several-keypads.md) | Name keypads, give each its own layout, and tell their overlays apart |
| [Troubleshooting](troubleshooting.md) | Keypad not found, read-only drive, Companion "busy", and more |

The screenshots come from the demo layout (`cuekeys init --example demo.json`) and are rendered by
`scripts/screenshots.py`, so they match the current version of the app.

For developers: [architecture](../architecture.md), [protocol](../protocol.md),
[extending](../extending.md), [adding a keypad](../devices.md).
